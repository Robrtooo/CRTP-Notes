# 2. Good practices

> [!summary] Résumé
> Bonnes pratiques pour relire et adapter un script PowerShell après analyse de détection. Contexte : [[What is PowerShell]].

See [[What is PowerShell]] for context.

## Bonnes pratiques de relecture

Cette note conserve l'idée d'origine : après passage d'outils d'analyse, il faut comprendre précisément quelle portion du script pose problème et l'adapter de façon raisonnée.

Once you have used your different tools to scan your scripts and modify them as needed, you may still have to review the code manually, even after using **DefenderCheck**.

It returns which part of the script is problematic and helps guide the next modification step.

## Approche recommandée

- Revenir à la ligne ou à la fonction signalée par l'outil.
- Comprendre si le problème vient d'une chaîne, d'un bloc de code ou d'une fonctionnalité précise.
- Réécrire le minimum nécessaire pour garder un comportement lisible en lab.

#### Exemple de transformation simple

- If a base64 string is flagged, one approach in a lab exercise is to transform its representation and rebuild it at runtime.

*Ex : If binary is Bonjour, go for ruojnoB and write a function to put it back as Bonjour*

PowerUp is a good tool to help you for obfuscation.
